# Prototype 01 — First Working System Map

## Status

**PROPOSED / PROTOTYPE**

This document is the first deliberately small working representation of the project's larger systems inquiry.

It is not a conclusion about banking, debt, poverty, capitalism, or civilization.

Its purpose is to test whether the project's architecture can take one person inside one system, expose the relationships, distinguish formal choices from materially available choices, and then fold the view back out.

---

# 1. First Perspective

### Starting question

> **A person needs something now and enters a system that provides it. What changes about the person's available choices after entering?**

The first perspective is deliberately human-scale.

### Perspective Contract

- **Observer position:** one person inside a system
- **Scale:** individual → immediate transaction → surrounding system
- **Time:** before entry → entry → obligation → attempted exit
- **Primary constraint:** an immediate unmet need
- **System under examination:** a mechanism that provides resources now in exchange for a future obligation
- **Primary question:** does the mechanism increase or decrease materially available choices over time?
- **Evidence status:** this prototype is a model structure, not empirical evidence
- **Known blind spot:** the specific terms, alternatives, and outcomes must be supplied by a real case before factual conclusions can be drawn

---

# 2. The Smallest Map

```
IMMEDIATE NEED
      ↓
AVAILABLE RESOURCES
      ↓
CHOICE
      ↓
ENTRY INTO SYSTEM
      ↓
RESOURCE RECEIVED NOW
      ↓
FUTURE OBLIGATION
      ↓
REQUIRED FUTURE CAPACITY
      ↓
AVAILABLE CHOICES CHANGE
      ↓
ATTEMPTED EXIT
      ↓
EXIT COST / EXIT ACCESS
      ↓
NEW SYSTEM STATE
      ↓
REFLECTION
      ↺
```

The important transformation is not simply:

> Need → resource

It is:

> **Need → resource now → obligation later → changed future choice set**

That transformation is what the prototype is designed to make visible.

---

# 3. Five Questions

At every point in the map, the observer asks:

### 1. Where am I?

What part of the system am I currently inside?

### 2. What am I dependent on?

What resource, institution, person, infrastructure, information, or condition must remain available for the current arrangement to continue?

### 3. What changed when I entered?

What new capability appeared?

What new obligation appeared?

What options disappeared, became harder, or became easier?

### 4. What choices are actually available now?

Do not count a choice merely because it exists formally.

Ask whether it is:

1. known;
2. technically possible;
3. legally available;
4. economically accessible;
5. physically accessible;
6. socially accessible;
7. durable.

### 5. Where is the exit?

What would allow the person to leave the arrangement without simply entering an equivalent or more restrictive arrangement?

What does the exit require?

---

# 4. Fold 1 — Before Entry

The person begins with:

```
NEED
  ↓
CURRENT RESOURCES
  ↓
KNOWN OPTIONS
  ↓
PERCEIVED CHOICE
```

The map must not assume that the person has complete information.

The person may not know every alternative.

Therefore:

> **Unknown alternative ≠ available alternative.**

This is one of the first tests of the system.

---

# 5. Fold 2 — Entry

The person enters a mechanism that provides a resource immediately.

Conceptually:

```
RESOURCE NEEDED NOW
        ↓
SYSTEM ENTRY
        ↓
RESOURCE RECEIVED
        +
FUTURE OBLIGATION CREATED
```

The prototype intentionally places **benefit and obligation next to one another**.

Receiving a resource is not itself evidence of harm.

Creating an obligation is not itself evidence of harm.

The question is what happens to the person's future capacity and choices.

---

# 6. Fold 3 — The Obligation

The future obligation creates a requirement for future capacity.

Conceptually:

```
OBLIGATION
    ↓
REQUIRED FUTURE CAPACITY
    ↓
INCOME / LABOR / ASSETS / TIME / OTHER RESOURCES
    ↓
FUTURE ACTIVITY
```

The phrase **required future capacity** is intentional.

A financial obligation is not physical energy.

But satisfying an obligation can require activity that depends on physical and human resources.

Therefore the prototype keeps separate layers:

- **Financial:** claims, obligations, prices, payments
- **Human:** labor, time, attention, skills, relationships
- **Physical:** energy, materials, transportation, buildings, infrastructure
- **Institutional:** rules, contracts, permissions, enforcement
- **Information:** knowledge, measurement, records, forecasts

These layers may interact without being treated as identical.

---

# 7. Fold 4 — Choice Set Transformation

The central test is:

```
CHOICES BEFORE ENTRY
        ↓
ENTRY
        ↓
NEW OBLIGATION
        ↓
REQUIRED FUTURE CAPACITY
        ↓
CHOICES AFTER ENTRY
```

The prototype asks:

> **Did the system merely provide a resource, or did it also alter the structure of future choice?**

Either answer is possible in a particular case.

The map does not decide in advance.

---

# 8. Exit Test

A proposed exit must be tested rather than merely named.

For each exit:

| Exit test | Question |
|---|---|
| Known | Does the person know it exists? |
| Possible | Can it actually be done? |
| Legal | Is it legally available? |
| Affordable | Can the person bear the cost? |
| Physical | Can the person physically reach/use it? |
| Social | Can the person use it without unacceptable social barriers? |
| Durable | Does it actually reduce dependence rather than relocate it? |

### Exit equation

```
THEORETICAL EXIT
      ↓
ACCESS CONDITIONS
      ↓
ACTUAL EXIT
      ↓
DURABLE CHANGE
```

An exit that simply transfers the same obligation somewhere else should be represented as a **transition**, not automatically as an exit.

---

# 9. Capture Test

The prototype uses the word **capture** descriptively.

It does not mean conspiracy, illegality, or malicious intent.

A system may produce increasing dependence without anyone explicitly designing that outcome.

The test is:

```
ENTRY
  ↓
DEPENDENCE
  ↓
OBLIGATION
  ↓
REINFORCEMENT
  ↓
FEWER PRACTICAL ALTERNATIVES
  ↓
EXIT BECOMES MORE EXPENSIVE
```

If the sequence does not occur in a real case, the capture hypothesis should not be applied.

---

# 10. Benefit / Cost / Risk / Exit Matrix

Every map node should eventually be able to answer:

| Dimension | Question |
|---|---|
| Benefit | Who gains something from this step? |
| Cost | Who bears a cost? |
| Risk | Who is exposed if the arrangement fails? |
| Control | Who can change the arrangement? |
| Exit | Who can leave? |
| Learning | Who receives information about the consequences? |

This prevents the map from becoming a one-directional story.

---

# 11. Worked Abstract Example

This is deliberately abstract.

### State A — Need

A person lacks a resource required immediately.

**Known:** an immediate need exists.

**Unknown:** the person's complete set of alternatives.

### State B — Entry

The person obtains the resource through an arrangement that creates a future obligation.

**Benefit:** immediate resource access.

**New condition:** future obligation.

### State C — Obligation

The person now needs sufficient future capacity to satisfy the obligation.

Possible required resources could include:

- income;
- labor;
- time;
- transportation;
- assets;
- institutional access;
- information.

The map does not assume which one matters most.

### State D — Changed Choice Set

The person now evaluates future choices while carrying the obligation.

Some options may remain.

Some may become less accessible.

Some may become more accessible because the initial resource solved an immediate constraint.

This is an empirical question.

### State E — Exit Attempt

The person identifies an alternative.

The map asks:

> Is this actually an exit, or merely another entry?

### State F — New System State

After the attempted exit, the person may have:

- greater independence;
- equivalent dependence in a different system;
- greater dependence;
- unresolved dependence;
- insufficient information to determine the result.

The prototype does not select among these outcomes.

---

# 12. Fold Back

After examining the individual transaction, return to the original perspective.

```
INDIVIDUAL
   ↓
TRANSACTION
   ↓
OBLIGATION
   ↓
FUTURE CAPACITY
   ↓
CHOICE SET
   ↓
EXIT
   ↓
NEW STATE
   ↓
FOLD BACK
   ↓
INDIVIDUAL INSIDE LARGER SYSTEM
```

The observer should now ask:

> **What did the zoomed-in view reveal that was invisible from the starting frame?**

And:

> **What did the zoomed-in view fail to show because it was too small?**

That second question is essential.

A zoomed-in representation can hide larger causes.

If Prototype 01 works, the same structure can be folded outward:

---

# 14. What This Prototype Is Testing

This prototype is successful if a reader can:

1. identify the starting perspective;
2. follow a transformation from one system state to another;
3. see benefits and obligations simultaneously;
4. distinguish financial, human, physical, institutional, and information layers;
5. distinguish formal choice from materially available choice;
6. identify a proposed exit;
7. test whether the exit is actually accessible;
8. see what becomes visible after zooming in;
9. see what becomes hidden by zooming in;
10. fold the analysis back into the larger system.

If it cannot do these things, the architecture needs revision before the project expands.

---

# 15. What This Prototype Does Not Claim

This prototype does **not** establish that:

- debt is inherently harmful;
- banking is inherently extractive;
- financial systems intentionally capture people;
- interest is physical energy;
- scarcity is caused by money;
- economic activity is equivalent to energy consumption;
- civilization is literally a biological organism;
- every apparent exit is false;
- every system has the same structure.

Those are separate questions requiring evidence.

---

# 16. The First Actual Experiment

The next development step is to replace the abstract example with **one documented real-world case**.

The case should be small enough to trace from:

```
BEFORE
→ ENTRY
→ BENEFIT
→ OBLIGATION
→ CHANGED CHOICE
→ EXIT ATTEMPT
→ OUTCOME
```

The purpose is not to prove the larger theory.

The purpose is to determine whether the map can faithfully represent reality without losing the person inside it.

---

## Working Principle

> **Start small enough to see the whole transformation. Then fold outward only after the transformation can be followed without ambiguity.**

And when the map becomes complicated:

> **Do not immediately add more nodes. First ask whether the perspective itself needs to change.**
