# California Product Closure — Archive Package

## Classification
Project / policy-research body.

## Provenance
This package preserves the product-closure project developed in conversation and maintained as a separate project repository. It is archived here because the existing `apo` tree did not contain an adequate named package for it.

## Core question

> Does the system remain legible and practically usable at the moment an adult resident is holding the actual object?

The project examines product lifecycle closure: repair, reuse, return, recycling, recovery, and lawful disposal.

## Core principle

> A product lifecycle should include its closure.

A responsible producer, system, or public authority should provide a reasonably accessible pathway for material/product to reach an appropriate endpoint. This does not mean every product must be recyclable. It means responsibility, information, funding, access, and physical capacity should be clear enough for a resident to act.

## Practical distinctions

- Identification is not disposition.
- Collection is not closure.
- Movement is not closure.
- A service can exist without being practically accessible.
- A webpage is not a disposal pathway unless the necessary physical, technological, financial, and institutional capacity exists.
- If no verified pathway exists, that absence can be treated as a policy/capacity signal rather than automatically as resident failure.

## Resident Outcome Test

After an intervention, ask whether an ordinary resident could actually do something differently, more easily, safely, or reliably.

Possible evidence states:
- demonstrated
- reported but not independently verified
- partial
- no demonstrated change
- unknown
