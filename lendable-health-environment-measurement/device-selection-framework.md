# Device Selection Framework

Status: proposed evaluation method; no device has been approved by this archive.

The first-generation collection should optimize for usable outcomes rather than maximum technical capability.

The 10-minute autonomy test
----------------------------
Give a candidate device to a first-time user with no staff assistance. Can they:

1. turn it on;
2. understand what it measures;
3. position it correctly;
4. take a measurement;
5. recognize success/failure;
6. repeat it;
7. connect/export data if required;
8. save the result;
9. understand its basic meaning and limitations;
10. finish without corrupting or losing the record?

If not, exclude it or redesign the lending workflow.

Candidate categories
--------------------
Health: blood-pressure monitor; pulse oximeter; thermometer; weight measurement; other validated home-health instruments.

Home/environment: humidity/temperature; particulate matter; CO2; carbon monoxide; radon; noise; moisture; thermal imaging; water-quality measurements; electrical-use measurement; other housing-condition instruments.

Evaluation fields
-----------------
Measurement/unit; intended use; accuracy/precision; regulatory status; home-use labeling; calibration; maintenance; sanitation; power; offline capability; Bluetooth/USB/Wi-Fi/cloud dependencies; local storage; export format; API/FHIR possibility; interface clarity; accessibility; training required; failure modes; privacy exposure; device identity/provenance; loss/theft controls; acquisition/replacement cost; lending precedent; insurance/liability; evidence of usefulness; unresolved questions.

Selection principle
-------------------
A technically impressive device is not automatically a good library device. Favor simple, validated instruments that ordinary borrowers can operate correctly and that do not create unnecessary network or data exposure.

"Smart" should mean the device helps the user succeed, not that it continuously reports the user to a cloud service.
