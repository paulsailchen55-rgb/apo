# Institutional Routing

## Purpose

An institutionally useful translation is not complete until the person can identify where the issue can actually be taken.

The routing layer maps an issue to possible recipients while preserving the distinction between the recipient's authority and the person's claim.

## Routing record

For each possible destination, record:

- who the recipient is
- what authority or role the recipient has
- what the recipient can act on
- what the recipient cannot decide
- what documents or evidence may be needed
- available communication method
- relevant deadline
- date sent
- response received
- next procedural step

## Multiple destinations

A single issue may legitimately have several destinations. The system should not force every problem into a single institutional channel.

For example, a housing issue might have separate routes to:

- a property manager
- a housing authority
- an accommodation contact
- a tenant organization
- legal assistance

Each route can require a different representation of the same underlying experience.

## Translation by recipient

The same source record can be transformed for different audiences without losing the common provenance chain.

```text
ONE HUMAN EXPERIENCE
        |
        +--> property-management request
        +--> accommodation request
        +--> grievance
        +--> legal-information request
        +--> collective-action record
```

The recipient-specific document should link back to the source rather than becoming the new source of truth.

## Authority map

The routing system should explicitly distinguish:

- person reports an experience
- AI identifies a possible issue
- governing authority establishes a rule
- institution receives a request
- institution makes a decision
- person accepts, disputes, or appeals the decision

The AI should not imply that identifying a possible legal or procedural issue is itself an official determination.
