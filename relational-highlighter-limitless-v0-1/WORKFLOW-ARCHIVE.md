# Workflow Archive

## Version 0.1 — Freeze Point

### Starting question

How did modern AI memory evolve from databases, and what is the deeper goal of an AI memory system?

### Key transition

The discussion moved from database architecture toward **human-controlled memory**.

The first major formulation was:

> Design a human-controlled memory protocol for AI.

### Highlighter insight

The user introduced the human reading experience in which a particular word, phrase, or idea seems to “pop out” from an entire page.

This led to the distinction between:

- the entire information field
- the thing that becomes salient
- the context that gathers around it
- the meaning that emerges afterward

### *Limitless* connection

The bicycle/light sequence in *Limitless* was recognized as a useful fictional metaphor for the moment when information becomes newly salient.

The movie was then reframed as a conceptual laboratory rather than as a literal scientific model.

### Three/four-highlight insight

The user proposed that relational highlighters may work in groups of **three or four**, with older highlights persisting as a kind of **ghost memory**.

New observations can overlap with those latent traces.

Set-theoretic overlap may produce an emergent relationship.

### Frozen formulation

> **The relational highlighter is not a memory item. It is a temporary field of attention formed by several highlighted observations whose relationships could generate a new observation.**

### Next workflow

Do not jump directly to implementation.

First define the 3–4 highlight mechanism:

- activation
- persistence
- decay
- ghost state
- reactivation
- overlap
- emergence
- human confirmation
- retention
- forgetting

Then test it with small examples before selecting database technology.

### Provenance note

This folder is an archive of an evolving concept. Terminology and architecture may change. Earlier formulations should remain available rather than silently overwritten.
