# Workflow Archive

## Standard project workflow

1. Capture the original idea without prematurely resolving it.
2. Separate facts from calculations, hypotheses, and speculation.
3. Identify the system being studied.
4. Map inputs, interfaces, transformations, outputs, and feedback loops.
5. Preserve difficult questions and objections.
6. Test claims against primary or authoritative sources where possible.
7. Record what remains unknown.
8. Build the research paper / main project document.
9. Add hard-to-discuss questions and research questions.
10. Add archival notes so later revisions do not erase the reasoning path.
11. Add engagement steps only after the evidence structure is clear.
12. Post files independently to GitHub so one failed write does not lose the project.

## Evidence labels

- **KNOWN:** directly supported by a reliable source or documented observation.
- **CALCULATED:** derived from stated inputs with reproducible calculation.
- **TESTED:** supported by an explicit test, comparison, dataset, or experiment.
- **PROPOSED:** a suggested framework, metric, or mechanism awaiting testing.
- **SPECULATIVE:** exploratory possibility with insufficient evidence.
- **UNKNOWN:** not established.

## Preservation rule

When a new finding changes the direction of the project, append it rather than deleting the earlier question. The evolution of the research is part of the archive.

## Posting rule

For a new idea, keep the project self-contained. Do not merge or delete duplicate folders merely for tidiness without reviewing what each contains.
